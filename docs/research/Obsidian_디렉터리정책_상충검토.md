# Obsidian 커뮤니티 디렉터리 정책 검토 및 프로젝트 결정

작성일: 2026-11-05 · 공식 문서 확인일: 2026-11-05 · 관련 항목: `0-ENV-08`

## 1. 조사 범위와 적용

2026-11-05 기준 Obsidian 공식 개발자 문서의 정책·제출 요건·FAQ·제출 절차·관리 절차·조직 문서를 대조했다. 정책은 공식 Community Directory에 등재하는 플러그인에 적용된다. 등재하지 않는 플러그인 설치에는 이 정책이 적용되지 않지만, 프로젝트는 커뮤니티 디렉터리 등재를 목표로 이 요건을 출시 기준으로 삼는다.

| 문서 | 공식 주소 |
|---|---|
| Developer policies | https://docs.obsidian.md/Community+directory/Developer+policies |
| Submission requirements for plugins | https://docs.obsidian.md/Community+directory/Submission+requirements+for+plugins |
| Frequently asked questions | https://docs.obsidian.md/Community+directory/Frequently+asked+questions |
| Submit your plugin | https://docs.obsidian.md/Plugins/Releasing/Submit+your+plugin |
| Manage your plugin or theme | https://docs.obsidian.md/Community+directory/Manage+your+plugin+or+theme |

이 검토는 프로젝트 자체 MIT 라이선스와 구별된다. MIT 표기나 저작권자·공개 승인 확인은 제3자 런타임·모델·디코더의 라이선스 검토 또는 Obsidian 정책 준수를 대신하지 않는다. artifact별 검토는 `0-ENV-16`에서 별도로 수행한다.

## 3. 런타임·모델 설치 정책 결정

공식 문구는 플러그인이 "Install or update themselves or their dependencies" 하지 못하도록 한다. 이 문서에서 런타임 실행 파일과 대형 모델 파일이 의존성에 포함되는지 별도로 정의하거나 예외를 인정하는 문구는 확인되지 않았다. 불확실한 해석이나 사용자 동의에 의존하지 않도록 본 프로젝트에서는 이를 의존 구성요소로 취급한다.

**결정:** 플러그인에 런타임·모델 다운로드, 설치, 교체·업데이트, 제거 기능을 넣지 않는다. 사용자가 플러그인 외부에서 직접 취득·설치·관리하며, 플러그인은 사용자가 지정한 파일의 경로·버전·해시·호환성과 시험 실행만 확인한다. README는 사용자가 별도로 내려받는다는 점과 로컬 파일을 vault 밖에서 읽고 실행하는 이유를 공개한다. 플러그인 자체의 네트워크 사용이 추가되면 해당 원격 서비스와 목적을 README에 구체적으로 공개하고 정책을 다시 검토한다.

이 결정은 보수적 정책 적용이다. Obsidian이 이 구체 사례를 별도 판정했다는 뜻은 아니다. 향후 자동 설치 기능을 제안하려면 구현 전에 공식 담당자의 명시적 확인과 정책 재검토가 필요하며, 확인 전까지는 기능을 추가하지 않는다.

| 항목 | 현재 결정·상태 | 후속 조치 |
|---|---|---|
| MIT와 권리자 | 프로젝트 자체 코드는 MIT. 저작권자 `에스넷시스템` 및 공개 승인을 사용자 확인으로 기록 | `LICENSE`와 프로젝트 메타데이터 유지. 외부 구성요소 권리 검토는 `0-ENV-16`에서 완료 |
| 네트워크·vault 밖 접근 | 플러그인 자체 네트워크·텔레메트리는 사용하지 않는다. 사용자가 지정한 vault 밖 런타임·모델 경로는 읽고 실행한다. | README 공개 내용을 구현 동작과 일치시킨다. 제품이 실제로 vault 밖 오디오를 읽도록 확장될 경우 별도 공개와 정책 검토를 한다. |
| 저장소·디렉터리 등록 | 등록 전에 저장소 위치·Owner·플러그인 ID를 결정해야 한다. 기존 ID는 게시 후 변경할 수 없다. | `0-ENV-02`에서 공개 범위와 저장소 위치를 결정한 뒤 Directory 제출 양식을 사용한다. 조직 Owner는 운영상 결정 사항으로 남긴다. |
| 메타데이터·릴리스 | `isDesktopOnly: true`; `minAppVersion`은 잠정값 | 최소 버전, 설명 길이·문장부호, 버전 일치, 필수 릴리스 자산, 샘플 코드 제거와 자동 검사를 제출 직전에 점검한다. |
| 아티팩트·고지 | 프로젝트 MIT와 별개로 실제 배포물은 미검토 | `0-ENV-16`에서 정확한 버전·출처·해시·라이선스·고지·재배포 의무 및 SBOM을 확정한다. |

플랫폼 요건 확인은 완료했지만 공개 릴리스 승인은 완료되지 않았다. `0-ENV-16`의 artifact별 검토와 출시 직전 제출 체크리스트를 통과하기 전에는 공개 릴리스를 진행하지 않는다.

## 5. 참고 사항

- Obsidian 상표 사용은 코드·플러그인 라이선스와 별도다. 플러그인 이름이나 설명이 공식 제휴·보증을 암시하지 않도록 하고, 상표 사용이 필요한 경우 Obsidian 상표 정책을 별도로 확인한다.
- 프로젝트가 이후 원격 서비스, 텔레메트리, 결제 또는 vault 외부 오디오 접근을 추가하면 README 공개와 정책 검토를 구현 범위 확정 전에 다시 수행한다.
- 문서에서 사용하는 "사용자 관리"는 사용자가 플러그인 외부에서 실행 파일·모델 파일을 취득·설치·업데이트·제거한다는 뜻이다. 플러그인의 로컬 경로 확인과 시험 실행은 파일 설치·갱신을 수행하지 않는다.
