# 0-OBS-01: Audio recorder 산출물 이벤트 감지

## 시험 조건

- 시험일: 2026-11-02
- Obsidian Desktop: 1.14.4
- 시험 볼트: `PlugVaults`
- 감지 방식: 공개 API `app.vault.on("create")` 및 `app.vault.on("modify")`
- 기록 정보: 파일 확장자, 크기, 수정 시각, 이벤트 종류
- 오디오 내용과 파일 경로는 읽거나 기록하지 않음

## 결과

짧은 코어 Audio recorder 녹음에서 다음 이벤트를 관찰했다.

| 이벤트 | 횟수 | 파일 형식 | 파일 크기 |
|---|---:|---|---:|
| `create` | 1 | `.m4a` | 77,134 bytes |
| `modify` | 0 | - | - |

`Vault`는 공개 `Events` API를 상속하고, `Events.on`은 `create`·`modify` 이름의 이벤트 구독을 지원한다. 실제 코어 recorder 산출물은 `.m4a` 파일 생성 이벤트로 감지됐다. 이 시험에서는 녹음 도중 파일 수정 이벤트가 관찰되지 않았으므로, 진행 중 변경이나 녹음 종료를 `modify` 이벤트만으로 판단할 수 있다고 결론 내릴 수 없다.

## 결론 및 후속 작업

- 공개 API만으로 녹음 산출물의 **생성** 감지는 가능함을 확인했다.
- 실제 recorder의 파일 **수정 이벤트**는 이번 시험에서 확인되지 않았다. 녹음 시작·종료 시점이나 파일 안정화 판정까지 입증한 것은 아니다.
- 파일 크기·수정 시각의 안정화 조건은 `0-OBS-02`, 노트 링크 삽입 시점은 `0-OBS-03`에서 별도로 시험한다.
- 시험용 이벤트 관찰 코드는 제거했다. `PlugVaults`에서만 임시 활성화한 코어 Audio recorder 설정을 원래 상태(비활성)로 복원했고, 관찰 데이터만 삭제했다. 생성된 테스트 녹음 파일은 수정하거나 삭제하지 않았다.
