# 0-OBS-03: Audio recorder 노트 링크 삽입 시점

시험일: 2026-11-05 · Obsidian Desktop 1.14.5 · 시험 볼트: `PlugVaults`

## 1. 시험 방법

- 시험 볼트의 업무 데이터가 아닌 활성 노트에서 코어 Audio recorder로 짧은 녹음을 만들었다.
- 볼트 파일 시스템의 이름·수정 시각 이벤트를 관찰하고 `.obsidian` 내부는 제외했다.
- 녹음 파일명과 노트 내용은 출력하거나 기록하지 않았다. 파일 생성 시각과 변경된 Markdown 노트의 파일 시스템 수정 시각만 비교했다.
- 시험 후 변경된 노트에 해당 오디오를 가리키는 Obsidian embed가 존재하는지만 로컬에서 확인했다.

## 2. 결과

| 관찰 | 결과 |
|---|---|
| 새 오디오 파일 | `.m4a` 1개 |
| 변경된 Markdown 노트 | 1개 |
| 오디오 파일 수정 시각 | 20:02:53.197 |
| 노트 수정 시각 | 20:02:55.206 |
| 파일 수정 시각 간 차이 | 약 2,008 ms |
| 최종 노트의 오디오 embed | 확인 |

파일 시스템 시각 기준으로 오디오 파일 생성 후 약 2초 뒤 노트 파일이 수정됐다. 사후 확인에서 노트에 해당 오디오 파일을 가리키는 embed가 있었다. 링크 삽입 자체의 정확한 시각을 직접 기록한 것은 아니므로, 2,008 ms는 삽입 시각이 아니라 오디오와 노트의 파일 수정 시각 차이다.

## 3. 결론과 구현 시사점

- 이 시험에서 노트 embed는 오디오 파일 생성과 동시에 기록되지 않았다. 녹음 완료 후 파일 안정화만 확인하고 바로 처리하면 링크가 아직 반영되지 않았을 가능성을 고려해야 한다.
- 기존 `quietMs` 5초는 이 시험에서 관찰한 약 2초의 노트 수정 지연보다 길다. 다만 단일 녹음 결과이므로 다른 장치·vault 상태에서도 충분하다고 일반화할 수 없다.
- 자동 처리 구현 시 녹음 파일 안정화와 별도로 활성 노트의 링크/Embed가 해당 파일을 가리키는지 공개 MetadataCache로 확인한다. 링크가 확인되지 않으면 무기한 기다리지 말고 제한 시간 후 안내와 수동 파일 선택 경로를 제공한다.

## 4. 한계 및 후속 시험

- 실제 녹음 1회, 한 장치, 한 Obsidian 버전만 확인했다. 반복 횟수가 부족해 지연 시간의 분포와 링크 없는 경우의 동작은 미확인이다.
- 기록한 시각은 파일 시스템 LastWriteTime이며 Audio recorder 내부의 이벤트 발생 시각이나 링크 삽입 시각과 동일하다고 보장할 수 없다.
- 다른 노트가 활성화된 경우, 동시 녹음, 느린 vault, 동기화·복사로 유입된 오디오 파일은 시험하지 않았다.
- 지원 범위를 넓히기 전 추가 반복 시험에서 오디오 생성·노트 변경 순서와 최대 링크 반영 지연을 확인한다.
